# New API route

The one way to add a backend route and call it from a portal. Decision:
[ADR 0270](../adr/0270-der-vertrag-zwischen-go-und-frontend-entsteht-aus-der-go-registrierung.md).
Proxy rules, file flags and the session path in detail:
[frontend API and server boundaries](frontend-api.md).

## Who owns which part of the seam

| Part | Owner | Lives in |
|---|---|---|
| Handler, validation (`Bind`), permission, tenant transaction | The Go owner of the capability | its `http` role, e.g. `backend/modules/timetable/http/activities/http.go` |
| Contract: method, pattern, portals, query, request and response type, file and upload flags | The same owner | `RouteContracts()` returning `[]common.RouteContract` (`backend/api/common/route_contract.go`) beside the handler |
| Mount of the contract | The root | `backend/api/route_contracts.go` (`*ContractMounts`) |
| Route catalog line | Generated | `backend/api/testdata/routes/` (`TestFullProductionRouterGolden`) |
| Model, types, zod decoders, portal allowlists | Generated by `gencontract`; nobody edits them | `backend/api/contract/contract.json`, `frontend/src/lib/contract/*.generated.ts` |
| Portal proxy: allowlist, session, renewal, query filter, decoding, file streaming | Frontend platform | `frontend/src/lib/contract/catalog-proxy.server.ts`, one `app/api/<portal>/[...path]/route.ts` per portal |
| Backend transport (bearer, client identity, timeouts) | Frontend platform | `sendBackend` in `frontend/src/lib/backend-client.server.ts` |
| Browser call and mapping to view types | The feature | `frontend/src/lib/<domain>-api.ts`, `frontend/src/lib/<domain>-helpers.ts` |
| Named `route.ts` for browser-only behavior | The portal | `frontend/src/app/api/` (see the last section) |

Go is the source of every response shape. A type the frontend writes by hand
for a registered route (`Backend*`) is a second, unchecked copy; import the
generated type instead. `frontend/scripts/backend-wire-types.node-test.mjs`
(part of `pnpm run check`) finds such a copy by its form, whatever its name:
two `snake_case` fields of its own (a `Backend*` name: one), a generated type
imported under another name, or a type that only renames a generated one.

## Read route

Worked example, the same route from Go to the browser:
`GET /api/students/{id}/partial-absences`, staff portal.

1. **Handler.** Mount it in the owner's router inside the tenant
   transaction and behind its permission
   (`backend/modules/careplan/http/student_resource.go`):

   ```go
   r.With(common.RequiresPermission(permissions.UsersRead), withTx).Get("/{id}/partial-absences", rs.getStudentPartialAbsences)
   ```

   The handler answers through `common.Respond`
   (`partial_absence_handlers.go`); only that path writes identifiers as
   strings (`backend/api/common/wire_json.go`).
2. **Contract.** Add one line to the owner's route contracts in
   `backend/modules/careplan/http/route_contracts.go`:

   ```go
   {Method: "GET", Pattern: "/{id}/partial-absences", Portals: portals, Query: days, Response: []PartialAbsenceResponse{}},
   ```

   The pattern is relative to the mount. `Portals` names every portal that
   may call it (`common.PortalTenant`, `PortalParent`, `PortalSchool`,
   `PortalTraeger`, `PortalCaterer`, `PortalOperator`, `PortalPublic`). `Query`
   lists every parameter the handler reads (`days` is `from`/`to` as
   `QueryDate`). The generated route keeps the kind of each key. The catalog
   proxy drops unregistered keys and forwards every occurrence of registered
   keys without checking values. Identifiers are `ident.ID`
   (`sharedkernel/ident`) in every role, days are `calendar.Date`, closed value
   sets go in `Enums`. A count is an `int`; an amount or a count kept as
   `int64` says so with `contract:"number"`. The generator refuses a bare
   `int64`, the json option `,string`, a number under an identifier's name
   (`id`, `*_id`, `*_ids`), a numeric identifier in an answer and an answer
   whose shape depends on a query parameter. Do not format database IDs into
   Go strings. A field named like an ID that actually carries text, such as an
   RFID tag or a SEPA creditor ID, states why with `contract_text:"reason"`.
   The generator records the reason as `text_reason` in `contract.json`.
   `TestNoNumericIdentifierRatchet` checks numeric types and unmarked strings
   in the `api/`, `http` and `inbound` roles; only the kiosk device API (`/api/iot/*`, `/api/students/{id}/rfid`)
   keeps numbers and tags them `contract:"number"`, because PyrePortal
   v1.11.5 reads them. For JSON requests, `render.Bind` uses the strict
   ID decoder installed by `api/common`. A handler that reads its own JSON
   body uses `wire.Decode` or `wire.Unmarshal` (including custom request
   readers with nested IDs). Use `wire.NewDecoder` when the same stream
   must be checked for trailing data. Keep `encoding/json` for stored JSON, which
   continues to write and read numeric IDs.
   Keep IDs as strings in browser code, including when filtering or sorting;
   see [One transport](frontend-api.md#browser-calls).
   Give each Go field a concrete wire type; the generator rejects free JSON
   unless the field carries `contract_json:"<why its shape is open>"`.
3. **Mount.** A new contracts function gets one row in the matching
   `*ContractMounts()` list of `backend/api/route_contracts.go`, e.g.
   `{"/api/activities", timetableActivitiesHTTP.RouteContracts()}`. This
   route's function is mounted there under `/api/students` already. The
   generator refuses a contract the route catalog does not know.
4. **Catalog and contract.** A writing route needs its analytics
   classification first (below); without it the golden run writes nothing.
   Then, from `backend/`, in this order and once:

   ```bash
   ../scripts/run-go-toolchain.sh go test -tags=testhooks ./api/ -run TestFullProductionRouterGolden -update-goldens
   ../scripts/run-go-toolchain.sh go run . gencontract
   ../scripts/run-go-toolchain.sh go test -tags=testhooks ./api/ ./cmd/ -run 'TestFullProductionRouterGolden|TestTheCommittedContractIsCurrent'
   ```

   This writes the catalog line (`backend/api/testdata/routes/api/students.golden`),
   the type `PartialAbsenceResponse` and the entry
   `routes["GET /api/students/{id}/partial-absences"]` in
   `frontend/src/lib/contract/students.generated.ts`, and the allowlist entry
   in `portals.generated.ts`. Commit all of them; `TestTheCommittedContractIsCurrent`
   fails on a stale file.
5. **Backend test.** A router test answers the route
   (`backend/modules/careplan/http/partial_absence_replace_test.go`). CI's
   `TestEveryRegisteredRouteIsAnsweredInATest` (`backend/api`) fails on a
   registered JSON route no test answers.
6. **Browser call.** The domain client calls `bffJson` (`frontend/src/lib/bff-fetch.ts`)
   with the portal and the route's catalog key; the generated entry types the
   path parameters, the query, the body and the answer
   (`frontend/src/lib/student-partial-absences-api.ts`):

   ```ts
   const rows = await bffJson("tenant", "GET /api/students/{id}/partial-absences", {
     params: { id: studentId },
     query: { from, to },
   });
   return rows.map(mapPartialAbsence);
   ```

   Pass `from` and `to` as `YYYY-MM-DD` strings, never as numbers or
   timestamps. For both `bffJson` and `bffFile`, `QueryID` takes a string,
   `QueryInt` a number and `QueryBool` a boolean. `QueryString` takes a
   string or one of its registered `Values`; `Repeated: true` takes an
   array of the corresponding type. The browser helper encodes the values;
   Go checks format and validity. The compile-time examples in
   `frontend/src/lib/bff-fetch.test.ts` guard against the old untyped query.

   `mapPartialAbsence` maps to the view type. A failure throws an `ApiError`
   for the shared error path; `errorMessage` keeps a client's own text.
   Another portal is the first argument, with a pattern of that portal:
   `bffJson("parent", "GET /parent/me/notifications/feed/")`,
   `bffJson("org", …)`, `bffJson("platform", …)`; every portal has a real
   example in [Browser calls](frontend-api.md#browser-calls), with the rules
   for 204, 401, a missing `data` and the guards against the old helpers and
   hand-written wire types.
   Components load through `useSWRAuth` and a key factory of `~/lib/swr`.
7. **No route file.** The staff portal's catch-all `app/api/[...path]/route.ts`
   serves the path. Other portals call `/api/<portal>/…` for the backend's
   `/<portal>/…`; the prefix table is in
   [Portal proxy](frontend-api.md#portal-proxy-2352).

Also part of a read route, from [backend/CLAUDE.md](../../backend/CLAUDE.md):
a list registers a query budget scenario; a paged list answers through
`common.RespondPaginated` and registers `Paginated: true`; a user-facing
feature ships seed data; the architecture check and `check-changed.mjs` run
before push.

File links and browser navigations use `bffFileHref` with the registered GET
file key, typed path parameters and query. Use `bffFile` when the caller
reads the response itself. Use `bffPath` with a registered key for other
BFF addresses. The BFF route guard scans production source for retired
forwarding helpers and handwritten registered addresses, including templates
and concatenations that refer to constants or helper returns.

## Write route

Same steps; the contract names the body type, and the client sends it typed
(`saveStudentPartialAbsence` in the same client file):

```go
{Method: "POST", Pattern: "/{id}/partial-absences", Portals: portals, Request: PartialAbsenceRequest{}, Response: PartialAbsenceResponse{}},
```

- Go's `Bind` validates and answers 400 with field errors; the generated
  request type has only optional fields and repeats no rule.
- Every route whose handler reads a body names its type in `Request`, a
  file export too. A test that reaches a handler reading a body its contract
  does not type fails the answer check (`api/common/answer_contract_test_helpers.go`),
  through the whole router or a route-sized one whose pattern fits one
  registered route. A file answer does not pass that check, so its `Request`
  rests on this rule and review.
  A Go type that a body and an answer both carry is generated twice: the
  answer keeps its name, the body is `<Name>Input` with optional fields.
- A route without an answer body registers `NoData: true`.
- A route whose body carries a password or a code names why it must not be
  sent twice in `NoRetryAfterRenewal`.
- A POST that commits nothing its caller asked for (a preview, a search)
  names why in `NoCommit`. When its answer does not match the contract, the
  proxy then offers a retry; every other write asks to reload.
- After the write, the component refreshes its SWR family with
  `useInvalidateFamily`.
- Renaming or removing a registered field or route takes one release marked
  `Deprecated` / `DeprecatedFields`; `scripts/check-contract-compat.mjs` fails
  otherwise.
- A deprecated write that refuses every request for its last release (an old
  save without read state, ADR 0311) names why in `Refuses`. A test that sees
  its refusal through the route's full path answers it for
  `TestEveryRegisteredRouteIsAnsweredInATest`.

### Registers a write route touches

Checked on a copy of `POST /api/students/{id}/partial-absences` (#7811).
Each register fails a named check when the entry is missing; none of them
takes an exception for a new route.

| Register | Entry for the example | Check that fails without it |
|---|---|---|
| Analytics classification, `backend/analytics/core_actions.go` | `{http.MethodPost, "/api/students/{id}/partial-absences"}: event("absence_reported")`; a write no one counts says `notCaptured` | `TestFullProductionRouterGolden` (“writing routes without a core-action classification”); rule: `.claude/rules/usage-analytics.md` |
| Module rule, `backend/api/module_routes.go` | none: `{"/api/students", moduleRouteBasis}` covers it; a new path prefix needs a rule and, if borderline, a reason in `docs/reference/modulschalter.md` | `TestFullProductionRouterGolden` (“these routes belong to no module”) |
| Facade budget, `backend/test/module_facade_width_ratchet_test.go` and `module_facade_method_set_ratchet_test.go` | none: the handler calls the existing `PartialAbsenceService.CreatePartialAbsence` | `TestModuleFacadeWidthRatchet`, `TestModuleFacadeMethodSetRatchet` |
| Pass-through register, `backend/architecture/passthrough/` (ADR 0075, 0090) | none for a handler with branching; a new one-call method is a new entry | `scripts/backend-architecture.sh check` (“unregistered method”, “changed method evidence”) |
| Command effects, `backend/architecture/command-effects/` | none unless a port's call path changes | `scripts/backend-architecture.sh check` (“binding changed”) |

- **Facade budget.** An exported interface of a module's public package has
  at most 12 methods; adding one to a wider facade (`ActivityService` has 34)
  needs an ADR. Declare instead a narrow port with the one method in the
  consuming `http` package and let the root bind the capability to it
  (`.claude/rules/backend-conventions.md`, Rule 16).
- **Pass-through.** The scanner (`backend/internal/passthrough/predicate.go`)
  counts an exported method with a named receiver, at most 14 body lines and
  exactly one call through a field of the receiver: `rs.Service.Create(…)`,
  and also a getter `return x.ID.Int64()`. A conversion `int64(x.ID)` is no
  call. Changing the body of a registered method updates its evidence text;
  a new one needs a decision (ADR 0075).
- **Command effects.** Renaming, adding or removing a function on a port's
  call path changes its digest. Regenerate with
  `scripts/backend-architecture.sh effects`; a binding that is a named
  exception needs an ADR, the others a changed `reason`.
- **Permission and module of a write into another area.** The route takes
  the permission of the data it writes (`backend/auth/authorize/permissions`),
  not of the page that calls it, and its module follows its path prefix. The
  write itself goes through the owning module's capability or a workflow
  (ADR 0067), never through the calling module's store.

## File and upload route

- **File answer:** `File: true` instead of `Response`. Example:
  `GET /school/class-day/absence-list/export` in
  `backend/modules/classday/http/route_contracts.go`; the browser opens
  `/api/school/class-day/absence-list/export?…`
  (`frontend/src/lib/school-class-day-api.ts`). The handler sets
  `Content-Type` and `Content-Disposition`; the proxy streams the bytes,
  `private, no-store`.
- **Upload:** `Multipart: true` with `MaxBodyBytes` and `TooLargeCode`
  instead of `Request` (`POST /api/students/{id}/photo` in
  `backend/modules/peopledirectory/inbound/students/route_contracts.go`). The
  handler checks size, extension and content.
- Browser cache, conditional GET, public token links and public uploads are
  flags of the same contract (`PrivateCache` or `FileCache`, `ConditionalGet`,
  `PublicFile`, `PublicUpload`); rules in [Portal proxy](frontend-api.md#portal-proxy-2352).

## When a route needs its own `route.ts`

Only for what belongs to the browser and cannot live in Go:

- login, MFA, passkey and logout steps, session renewal and switching
  (`frontend/src/lib/login-route.server.ts`, `frontend/src/lib/logout-route.server.ts`);
- the SSE pipe (`app/api/sse/events`, `app/api/parent/sse/events`,
  `app/api/school/sse/events`) and the client log routes;
- a BFF cache or cookie the write must change: `settings/values/[key]`
  purges the cached tenant lookup, `demo/access/sessions` sets the demo cookie;
- a hand-off for a path on the catalog proxy allowlist that Next would give
  to a neighbouring route file (`catalogProxyUnder`); `app/api/catalog-route-selection.test.ts`
  fails when one is missing.

One named exception: `app/api/enrollment/form-bootstrap/public/[tenantSlug]/[phaseId]/route.ts`
adds the signed-in Staff profile to the public form. Both backend requests
use their generated entries. #5018 tracks moving the projection to Go; the
browser caller is allowlisted for exactly this address.

Such a JSON route stays typed: its `common.RouteContract` names `RouteFile`,
one sentence why the route file serves it (`common.RouteFileSession` for a
session step), beside its portal, `Request` and `Response` (or `NoData`,
`File`, `Multipart`). `Plain: true` says the handler writes the data without
the envelope (`common.RenderJSON`). The generator writes its types, decoder
and route entry and lists that entry in `routeFileRoutes`, never in a proxy
allowlist. The named handler calls `contractGet(entry, options)` or
`contractWrite(entry, body, options)`, even without a session. Both fill the
route entry’s path with typed `params` and serialize its typed `query`. The session
step's Go tokens never reach the browser; put its BFF answer in
`frontend/src/lib/session-bff.ts` and call that entry with `bffJson`.
See [school switching](../../frontend/src/app/api/auth/switch-tenant/route.ts)
and [pre-session enrollment start](../../frontend/src/app/api/auth/mfa/enroll/start/route.ts).
`app/api/route-backend-paths.test.ts` checks entry use and rejects raw Go
response reads in named routes and server modules. A server caller of a
registered JSON route also uses its generated entry with `contractGet`
or `contractWrite`; the old generic JSON helpers are not an alternative.

The browser uses `bffJsonUncontracted` only from the remaining callers
listed by the lint rule. See [One transport](frontend-api.md#browser-calls).

A reshaping, an ID or format check or a second backend call for the same
screen moves into the Go handler; an aggregation of several reads is a Go
view (#5018). A file whose only code forwards to the
backend fails `app/api/proxy-routes.test.ts`; a file whose backend paths
are all in a proxy allowlist fails `app/api/route-backend-paths.test.ts`, as
does a `RouteFile` route no route file serves; a file in front of a proxied
path fails `app/api/catalog-route-selection.test.ts`.

## Routes outside the contract

A catalog line no portal calls for JSON registers `Outside` on its
`common.RouteContract` instead of types: a reason of a closed set
(`contractmodel.OutsideReasons`) and one sentence why
(`common.OutsideRoutes(reason, why, "METHOD /pattern", …)`):

| Reason | Applies to |
|---|---|
| `device` | the kiosk (PyrePortal) with its device key; it reads numeric IDs |
| `webdav`, `metrics`, `probe` | CalDAV, Prometheus, health and readiness |
| `stream` | a server-sent event stream |
| `public-api`, `webhook` | a machine API with its own description, a provider's callback |

Each line is named on its own, no prefix
(`backend/api/route_contracts_outside.go`); `contract.json` lists them under
`outside`, no generated TypeScript names them. Ordinary JSON is never a
reason: it gets a contract, through the proxy or `RouteFile`.
`TestEveryCatalogRouteHasAContractOrAReason` (`backend/api`) fails on a
catalog line that is not exactly one of proxied contract, `RouteFile`
contract or `Outside`. A new `Outside` line also fails
`scripts/check-contract-shrink.mjs` until a new ADR names its catalog line;
a new `RouteFile` route needs none.
